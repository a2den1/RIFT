# RIFT 마인크래프트 플러그인 — 개발 의뢰 프롬프트

아래 내용을 그대로 복사해서 플러그인을 만들 AI에게 주면 됩니다.
`<>` 로 표시된 부분만 실제 값으로 바꿔 주세요.

---

## 여기서부터 복사

당신은 Paper 서버 플러그인을 만드는 Java 개발자입니다.
`RIFT` 라는 마인크래프트 서버의 플러그인을 처음부터 만들어 주세요.
이미 운영 중인 웹사이트와 Supabase 데이터베이스가 있고, 플러그인은 **그 DB와 양방향으로 연동**되어야 합니다.

### 1. 환경

- Paper 1.21.x, Java 21
- 빌드: Gradle (Shadow 플러그인으로 의존성 포함)
- 외부 라이브러리는 최소화. HTTP 는 Java 표준 `java.net.http.HttpClient`, JSON 은 Gson 만 사용
- 데이터 저장소는 **Supabase(PostgreSQL) 하나만** 사용합니다. 로컬 yml/SQLite 에 게임 데이터를 이중 저장하지 마세요
- 단, 네트워크 장애 대비로 전송 실패한 갱신은 메모리 큐에 쌓아 두었다가 재시도해야 합니다

### 2. 서버 콘셉트 (기능 요구사항의 배경)

RIFT 는 **약탈 야생 + 7vs7 공식 리그** 를 함께 굴리는 서버입니다.

- **야생**: 땅 보호가 없습니다. 기지를 직접 짓고 남의 기지를 약탈할 수 있습니다. 오버월드와 네더 사용
- **직업**: 공격수 / 탱커 / 원거리 / 서포터 중 하나. 첫 접속 때 선택하며 야생과 리그에서 동일하게 적용
- **경제**: 개인 자금과 구단 자금이 분리. 개인 자금은 상점·유저 거래, 구단 자금은 계약금·이적료
- **일일 상점**: 매일 서버 전체에 동일한 랜덤 상품 4개. 매일 오전 6시 갱신
- **플레이 보상**: 접속시간 기반 보상 (AFK 도 접속시간으로 인정), 일일 퀘스트, 구리 던전, 워든
- **현상금**: 게임머니로 다른 유저에게 현상금을 걸 수 있고 여러 명이 걸면 누적. 처치자가 전액 획득
- **구단**: 최대 로스터 15명, 리그 참가 최소 12명, 경기 출전 7명. 구단주는 직접 출전 가능,
  부단장은 선택사항, 단장 직책 없음. 리그 승리와 플레이시간으로 인지도가 오르고 구간마다 구단 레벨 상승
- **계약**: 연봉 없음. 영입 시 계약금만 지급하고 계약 기간은 없음
- **공식 리그**: 7vs7 중앙 거점 점령전. 킬은 승리 조건이 아님. BO3 로 2세트 선취 시 승리.
  일반 유저 관전 금지

### 3. 반드시 구현할 게임 기능

#### 3-1. 직업
- 첫 접속 시 GUI 로 직업 선택 강제
- `/직업` 으로 현재 직업 확인
- 직업 변경은 **직업 변경권 아이템**을 소지했을 때만 가능
- 직업별 능력치 차등은 설정 파일(`jobs.yml`)로 조정 가능하게

#### 3-2. 편의 명령어와 PVP 제한
- `/tpa <플레이어>`, `/tpaccept`, `/tpdeny`
- `/home`, `/sethome`, `/delhome` (홈 슬롯 수는 권한 노드로 제어)
- `/금고` — 개인 보관함 GUI (칸 수는 권한 노드로 제어)

**PVP 태그**: 플레이어가 다른 플레이어를 때리거나 맞으면 전투 상태가 됩니다.
- 기본 지속 15초, 피격/공격 시마다 갱신 (config 로 조정)
- 전투 중에는 `/tpa`, `/home`, `/금고` 를 포함해 **도주·아이템 보호에 쓸 수 있는 모든 명령어를 차단**
- 전투 중 로그아웃하면 캐릭터를 즉시 사망 처리 (콤배트 로그 방지)
- 액션바에 남은 전투 시간 표시

#### 3-3. 경제
- 개인 자금과 구단 자금을 **별도 계정**으로 관리
- `/돈`, `/송금 <플레이어> <금액>`, `/상점`
- 일일 상점: 매일 정해진 시각에 서버 전체 공통 랜덤 상품 4개 생성. 갱신 전까지만 구매 가능
- Vault 연동은 선택. 하되 내부 경제를 Vault 에 종속시키지 마세요

#### 3-4. 현상금
- `/현상금 <플레이어> <금액>` — 건 사람의 개인 자금에서 차감, 대상에게 누적
- 대상을 처치하면 처치자가 전액 획득하고 현상금은 0으로 초기화
- 자기 자신에게는 걸 수 없음
- 같은 사람이 같은 대상에게 반복해서 거는 것은 허용 (누적)

#### 3-5. 구단
- `/구단 정보`, `/구단 초대`, `/구단 수락`, `/구단 탈퇴`, `/구단 자금`
- 구단 창설은 **웹사이트에서 처리**합니다. 플러그인은 창설 기능을 만들지 말고 DB 의 구단 목록을 읽기만 하세요
- 이적 승인도 웹에서 처리됩니다. 플러그인은 `profiles.club` 변경을 감지해 인게임 소속을 갱신하세요
- 계약금 지급은 인게임에서 처리: `/구단 계약 <플레이어> <계약금>` — 구단 자금에서 차감

#### 3-6. 공식 리그 (7vs7 점령전)
- 경기는 관리자가 `/리그 시작 <홈구단> <원정구단> <맵>` 으로 개시
- 중앙 거점 하나. 점령 게이지가 차오르며 일정 수치 도달 시 해당 세트 승리
- BO3, 2세트 선취 승리
- 경기 중 참가자 외 텔레포트/관전 차단
- 세트/경기 종료 시 결과를 DB `matches` 에 기록하고 `clubs` 의 승·패·인지도를 갱신

### 4. Supabase 연동

#### 4-1. 접속 정보

```yaml
# config.yml
supabase:
  url: "https://<프로젝트ID>.supabase.co"
  service-key: "<service_role 키>"   # 절대 외부에 노출 금지
sync:
  push-interval-seconds: 60      # 통계 일괄 전송 주기
  status-interval-seconds: 30    # 접속자 수 갱신 주기
  pull-interval-seconds: 120     # 구단/소속 변경 감지 주기
```

**보안 요구사항**
- `service_role` 키는 RLS 를 전부 우회합니다. `config.yml` 밖으로 절대 새어 나가면 안 됩니다
- 로그, 채팅, 오류 메시지, 예외 스택에 키가 찍히지 않게 하세요
- 플러그인이 키를 어떤 형태로든 클라이언트에 전송해서는 안 됩니다

#### 4-2. REST 호출 방식

PostgREST 를 씁니다. 공통 헤더:

```
apikey: <service_role>
Authorization: Bearer <service_role>
Content-Type: application/json
```

**모든 HTTP 호출은 비동기여야 합니다.** 메인 스레드에서 네트워크 요청을 하면 서버가 멈춥니다.
Bukkit 스케줄러의 async 태스크에서 처리하고, 결과를 반영할 때만 메인 스레드로 돌아오세요.

#### 4-3. 플러그인이 **쓰는** 데이터

**`players`** — 랭킹에 그대로 노출됩니다. `name` 이 고유 키입니다.

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `name` | text (unique) | 마인크래프트 닉네임 |
| `job` | text | 공격수 / 탱커 / 원거리 / 서포터 |
| `club` | text | 소속 구단 이름 |
| `kills` | int | PVP 킬 |
| `deaths` | int | 데스 |
| `playtime` | int | 누적 플레이 **시간** 단위 |
| `money` | bigint | 보유 게임머니 |
| `bounty` | bigint | 현재 걸려 있는 현상금 |

upsert 예시 (여러 명 한 번에 보내세요):

```
POST /rest/v1/players
Prefer: resolution=merge-duplicates
[{"name":"Aiden","job":"공격수","club":"NOVA","kills":412,"deaths":96,
  "playtime":389,"money":15970000,"bounty":4200000}]
```

**`profiles.xp`** — 웹 프로필의 경험치. `mc_name` 으로 대상을 찾습니다.
웹에서는 수정이 막혀 있고 **플러그인만 씁니다.**

```
PATCH /rest/v1/profiles?mc_name=eq.Aiden
{"xp": 1250}
```

`mc_name` 은 대소문자 무시 고유 인덱스입니다. 해당 닉네임의 프로필이 없을 수 있으니
(웹 가입을 안 한 유저) 404/0건 응답을 정상 상황으로 처리하세요.

**`server_status`** — 홈 화면 접속자 수. 행이 없으면 사이트가 접속자 수를 숨깁니다.

```
POST /rest/v1/server_status
Prefer: resolution=merge-duplicates
[{"id":1,"online_count":42,"updated_at":"2026-08-10T12:00:00Z"}]
```

**`clubs`** — 경기 결과 반영 시에만 갱신합니다. `name` 이 고유 키입니다.
`wins`, `losses`, `games`, `set_diff`(문자열, 예 `"+13"`), `reputation`, `titles`, `funds`

**`matches`** — 경기 결과 기록. `home`, `away`, `starts_at`, `map`, `home_score`, `away_score`,
`status`(`scheduled` / `live` / `finished`)

#### 4-4. 플러그인이 **읽는** 데이터

- `clubs` — 구단 목록, 구단주(`owner`), 로스터 수, 자금
- `profiles` — `mc_name`, `job`, `club`, `pronouns`
  웹에서 이적이 승인되면 `profiles.club` 이 바뀝니다. 주기적으로 읽어 인게임 소속을 맞추세요
- `matches` — 예정된 경기 일정 (`status = 'scheduled'`)

#### 4-5. 동기화 규칙

- **전송은 일괄로**: 플레이어마다 매번 요청하지 말고, 변경된 플레이어만 모아 주기마다 한 번에 upsert
- **변경 없으면 보내지 않기**: 더티 플래그로 관리
- **즉시 전송이 필요한 경우**: 플레이어 접속 종료, 서버 종료, 경기 종료
- **서버 종료 시** `onDisable` 에서 큐를 동기 전송으로 비우세요 (여기서만 블로킹 허용)
- 실패한 요청은 지수 백오프로 재시도하되, 같은 플레이어의 최신 값만 유지하면 됩니다
- 플레이타임은 **시간 단위 정수**입니다. 내부적으로는 초/틱으로 세되 전송할 때 변환하세요

### 5. 명령어와 권한

| 명령어 | 권한 노드 | 설명 |
|---|---|---|

### 6. 산출물

1. Gradle 프로젝트 전체 (`build.gradle.kts`, `settings.gradle.kts`)
2. `plugin.yml` — 명령어와 권한 전부 등록
3. 소스 구조 제안과 각 클래스 역할 설명
4. `config.yml`, `jobs.yml`, `messages.yml` 기본값
5. Supabase 연동 계층은 **한 곳에 모으고**, 게임 로직이 HTTP 를 직접 호출하지 않게 인터페이스로 분리
6. 빌드와 설치 방법 README

### 7. 주의사항

- 메인 스레드에서 네트워크·파일 I/O 금지
- 플레이어 데이터는 `UUID` 를 기준으로 관리하고, DB 로 보낼 때만 닉네임으로 변환하세요
  (닉네임 변경 대응). `players.name` 은 현재 닉네임 기준으로 upsert 합니다
- 한국어 메시지를 기본으로 하되 `messages.yml` 로 전부 바꿀 수 있게 하세요
- 코드에 하드코딩된 숫자를 남기지 말고 설정으로 빼세요
- 아직 정해지지 않은 값(직업 능력치, 점령 게이지 속도, 보상 수치 등)은
  **임의로 정하지 말고 설정 파일에 기본값과 함께 주석으로 표시**하고, 무엇을 정해야 하는지 목록으로 알려주세요

## 프롬프트를 주기 전에 준비할 것

1. **Supabase URL 과 `service_role` 키** — Project Settings → API 에서 확인.
   `anon` 키가 아니라 `service_role` 키입니다. 이 키는 절대 공개 저장소나 클라이언트에 올리지 마세요.
2. 웹의 `supabase/` 폴더에 있는 SQL 파일을 모두 실행해 두었는지 확인.
   플러그인이 쓰는 `players`, `server_status`, `profiles` 테이블이 필요합니다.
3. 아직 정하지 않았다면 미리 정해 두면 좋은 값
   - 직업별 능력치 차이
   - 점령 게이지가 차는 속도와 승리 기준치
   - 접속시간 보상의 간격과 금액
   - 일일 상점 상품 후보 목록
   - 구단 인지도 계산식과 레벨 구간
